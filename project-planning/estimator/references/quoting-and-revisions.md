# Quoting and revising estimates

## Fixed price

Keep the delivery estimate and the proposed client price visible as separate numbers when the user asks for both. Use the user's commercial terms for any margin, contingency, tax, or fees. If those terms are missing, give the supported labor range and ask which terms apply before presenting a fixed price. If an unresolved dependency could materially change the commitment, quote the bounded discovery separately or make the implementation price conditional on a verifiable assumption. State the included revision rounds and the event that triggers a scope review.

## Budget cap

Deduct known charges covered by the cap, then price the proposed labor at the supplied rate or role rates. Find the smallest release that preserves the core acceptance criteria, then list the deferred outcomes and their impact. Check the reduced scope against the same capacity, dependencies, and mandatory release work.

**Example.** The client has USD 5,000 at USD 100/hour. The proposed release is 44–62 hours. The cap covers 50 hours. If removing automated reminders leaves a usable release at 36–48 hours, offer that scope. Give reminders their own estimate when the client wants them.

## Scope change

Start from the previous estimate and state which assumption or requirement changed. Show the added, removed, or reworked packages and the resulting effort and cost. Recalculate the delivery window using the remaining work and dependencies. Treat costs already incurred separately when the client asks what remains to pay.

**Example.** A 40–56-hour release was estimated at USD 100/hour. The client adds a 6–10-hour export using the same developer. The revised estimate is 46–66 hours and USD 4,600–6,600. If the export is required before acceptance, schedule it against that developer's remaining capacity and update the acceptance milestone.

## Discovery before a quote

For an undocumented supplier integration, a discovery package might produce a read-only sample import, confirm authorization and rate limits, and document field mappings and retry behavior. Use those findings to bound implementation. If sample access is pending, list it as a kickoff condition and give the estimate for independent work separately.
