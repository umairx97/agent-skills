# Quotes and revisions

## Fixed price

If the user requests a delivery estimate and a proposed price, give these values separately. Use the user's terms for the margin, contingency, tax, and fees.

If these terms are missing, give the labor range that the available information supports. Ask which terms apply before you give a fixed price.

If an open dependency can significantly change the commitment, price the discovery task separately. Give that task a time limit. Alternatively, make the implementation price conditional on an assumption that the client can check.

Specify the number of revision rounds in the price. Specify the event that starts a scope review.

## Budget cap

Subtract the known charges from the cap if the cap includes these charges. Calculate the cost of the proposed labor with the applicable rates. Find the smallest release that meets the core acceptance criteria. List the results to defer. Explain the effect of each change. Check the reduced scope against the same project hours, dependencies, and necessary release work.

Example. The client has USD 5,000 at USD 100 per hour. The proposed release needs 44 to 62 labor hours. The cap covers 50 labor hours. If the release without automatic reminders is usable and needs 36 to 48 hours, offer that release. If the client requests the reminders, give a separate estimate for them.

## Scope change

Use the previous estimate as the starting point. State which assumption or requirement changed. List the work packages to add, remove, or change. Give the new effort and cost. Calculate the new delivery time from the remaining work and dependencies. If the client asks how much is still due, show the costs already incurred separately.

Example. The estimate for a release is 40 to 56 hours at USD 100 per hour. The client adds an export that needs 6 to 10 hours from the same developer. The new estimate is 46 to 66 hours and USD 4,600 to 6,600. If the client requires the export before acceptance, schedule it with the hours that the developer has available. Change the acceptance milestone to agree with the schedule.

## Discovery before a quote

If a supplier integration has no documentation, set a specific result for the discovery task. For example, prepare a read-only sample import. Confirm the authorization requirements. Check the rate limits. Record the field mappings and the behavior of retries.

Use the results to set the low and high values for the implementation work. If sample access is pending, specify it as a condition to start work. Give a separate estimate for work that does not need sample access.
